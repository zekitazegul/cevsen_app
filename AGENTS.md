# Project instructions

- Do not display the developer's personal name or email address in app screens. Route contact requests through Support and feedback. Keep the email recipient in message-draft routing, without rendering a separate email label on the form.
- Keep user-facing release notes short and describe only newly added features. Do not repeat earlier releases or include implementation details.
- Never commit signing keys, local configuration, generated builds, or device captures. Keep the source and required application assets reproducible in Git.
